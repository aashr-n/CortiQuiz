# CortiQuiz — Code Notes

## Project State: ✅ Builds successfully (iOS Simulator, iPhone 17, iOS 26.5)

## Architecture
- **SwiftUI + SceneKit** — pure Apple frameworks, no SPM deps
- **@MainActor @Observable** view models for each mode
- **MDLAsset** loads OBJ models via `SceneKit.ModelIO` bridge
- **ModelCache** singleton caches loaded SCNNodes to avoid repeated disk reads
- **Task.detached** for background model loading, `await MainActor.run` to commit state

## Data
- OBJ models in `BrainModels/`, converted from the atlas VTK triangle strips by `tools/convert_vtk_to_obj.py`
- `atlasStructure.json` in bundle root
- Only the 255 brain structures (252 files, including the 22 sulci) are used; muscles/skin (Model_4xxx, Model_3_skin) are filtered by `isBrainStructure`. The non-`1` copies of the sulci, colliculi and left optic nerve aren't referenced by the atlas JSON (it uses the `…1.obj` versions). See `todo.md` for removing the unused files.

## Known Considerations
- SCNSceneSource does NOT load .obj — using MDLAsset + SceneKit.ModelIO bridge
- iOS deployment target is 26.2; Swift 5 language mode with `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` and approachable concurrency
- Quiz L/R merging strips prefixes from names for answer matching
- Explode view: factor 0 is the natural layout (vertices are world-space; node positions are offsets)
- SceneKit `orthographicScale` is half the visible height: the slice camera shows 190 mm across 512 px (`MRISlicing.pixelsPerUnit`)
- SceneKit's `look(at:)` can't turn a node's default −Z view to face +Z (a 180° turn) and leaves it looking away; `MRISlicing.orientCamera` sets the camera basis directly
- iPhone is portrait-only; the app forces dark appearance (`UIUserInterfaceStyle = Dark`)

## MRI Mode Overhaul (2026-10-11)
- **Radiological orientation**: axial slices were upside down (anterior at the bottom). Axial is now seen from the feet and sagittal from the patient's left (face toward screen left); coronal was already radiological. A/P/S/I/R/L letters sit at the image edges (`MRIAxis.edgeLabels`), and a unit test checks them against the camera basis.
- **Framing**: the slice camera centers on the brain's bounds (it was centered on the origin, cutting ~7 mm off the occipital pole) and shows 190 mm instead of 180 mm.
- **Filled cross-sections**: the 2 mm slab clip showed only each structure's shell. The cut shader now discards everything in front of the plane; each structure draws its back faces (inside walls) in its color, and a background-colored twin draws front faces (outer walls). The twins sit `SliceRenderer.outsideDepthPush` (1 mm) deeper so a structure's inner wall beats a neighbor's coincident outer wall. 0.5 mm left black cracks in white matter; 2 mm let thin structures bleed through. Known leftovers: dark gaps where the cut point is inside no mesh (unlabeled space, or where neighboring smoothed meshes don't quite meet; taps there select nothing), and faint outlines of structures behind the cut in those gaps and below the brain.
- **Tap to identify**: `SliceRenderer.structureIndex(at:)` renders a frame with index-encoded flat colors (3 bits per channel) and reads one pixel. MRI Mode highlights the tapped structure (green, others dimmed) in every slice and on the mini brain, and shows its name and hierarchy.
- **MRI Mode UI**: full-width slice (mini brain moved below it, still not overlapping), pinch-zoom up to 4× with pan and a reset button, 1024 px settled frames, slice location in atlas mm ("S 12 mm"), ±1 mm step buttons (hold to repeat).
- **Mini brain**: shells at 12% opacity; slice plane sized to the brain's cross-section and drawn twice (depth-tested, plus faint on top) so it stays visible inside the brain; camera centered on the brain; highlighted structures draw on top.
- **MRI Quiz**: same renderer, so targets are solid filled regions; cuts at the middle of the classified slab (`SliceCandidate.cutCoord`); dimmed regions are opaque; header shows the slice location in mm; orientation letters.

## UI Refresh (2026-10-13)
- **X-ray ghost**: the faded "context" brain was every structure at 16% opacity, which stacked into a gray cloud that hid small targets. `NodeStyle.ghost` now draws only a faint cool rim glow (fresnel), blended additively without writing depth, so structures inside stay visible. One shader for both styles (`xray` uniform), so switching never recompiles. SceneKit disables blending for materials it considers opaque, so the ghost needs `blendMode = .add` (`.alpha` with a zero-alpha output just draws). The `xray` switch is set with actions disabled; an implicit animation would pair the old shader branch with the new blending for half its duration. The MRI mini brain uses the same ghost.
- **Highlights**: a new question's or card's structure pulses three times (`pulseHighlight`, an `SCNAction` built in a nonisolated function because SceneKit runs action blocks on its render thread); none with Reduce Motion. A mode's first restyle happens while it loads, before the scene is on screen, so it isn't animated.
- **Framing**: the camera fits the bounding sphere at 0.9× (was 1.18×) and `StageSCNView` applies the 30° field of view to the view's narrower side, so tall stages (iPad side by side) don't clip. SceneKit views fade in once `prepare` has uploaded the scene, instead of showing a blank first frame.
- **Layout**: `StageLayout` puts the 3D view or slice above a panel on iPhone and beside it when the window is wider than tall and ≥ 700 pt (iPad landscape), using `AnyLayout` so rotating keeps the 3D view. The panel hugs its content up to 62% of the height and scrolls past that (large text). The menu is a `NavigationStack` on iPhone and a `NavigationSplitView` on iPad (chosen by idiom, so it never switches at runtime): an iPhone's collapsed split view made the main thread wait on a lower-QoS thread at the start of every push (one priority-inversion warning per mode open in the UI tests; none with a stack). Modes leave through the `leaveMode` environment action, because `dismiss` can't pop a detail column's root. Column visibility is `.all` while no mode is open (otherwise iPad portrait hides the menu behind "Choose a mode") and `.automatic` once one is (portrait gives the mode the full screen). In the wide layout the panel is a card centered beside the stage.
- **Quiz panel**: a segment per question (green/red), the prompt turning into the verdict with the exact structure and a streak badge (3+), a tip row that Next replaces, and "See Results" on the last question. Header and action rows keep a fixed minimum height so the stage doesn't jump. The verdict, the Learn card's answer, and the hint are only built when shown: XCUITest (and so likely VoiceOver) still found views hidden with `opacity(0)` + `accessibilityHidden`.
- **Learn**: the card flips over (a `Transition` with an animatable rotation that hides each face past 90°; cross-fade with Reduce Motion). Hemisphere pairs show "Both hemispheres" and a side-less hierarchy.
- **Menu**: a hero brain (`HeroBrainView`: dark, every gyrus outlined by a rim glow, turning once every 48 s at 30 fps; white matter hidden; stops drawing as soon as a mode is picked) that lights up structures by quiz mastery (learning: light pink, mastered: gold; `ProgressStore.mastery`: ≥ 2 correct at ≥ 80% and not flagged). First launch shows a Start Here card instead of stats. About sheet: atlas credit, citation and license links, Reset Progress.

## Menu Redesign (2026-10-15)
- **Why**: the inset-grouped `List` menu (colored icon squares, chevron rows, large title) read as the Settings app. The menu is now one bespoke screen whose main controls are Liquid Glass tiles.
- **Composition** (`MainMenuView.swift`): no navigation bar on the menu (`toolbarVisibility(.hidden)`; modes still get theirs). Portrait: a centered New York wordmark ("Quiz" in the accent) over a tracked-caps tagline, the hero brain, then the panel. Wide (iPad landscape; `StageLayout`'s rule) is a spread: the brain the full height of the left, the wordmark heading a 440 pt column of stats and tiles on the right, through `AnyLayout` so rotating keeps the brain's scene (the wordmark is an `if` child before the brain or inside the panel, so the brain's structural position never changes). About floats as a glass circle in the top-trailing corner in both. The brain takes whatever height the rest leaves (min 220 pt): the content is given at least the screen's height inside a `ScrollView` that only scrolls when it must (accessibility text sizes, small phones). The panel: a stats row (accuracy, learning, mastered, best streak; Learning and Mastered carry the brain's pink and gold dots, so the numbers double as its legend; a `ViewThatFits` falls back to two by two when the row doesn't fit), or a welcome line on first launch; then the tiles, Learn as a full-width banner, 3D Quiz | MRI Quiz, 3D Atlas | MRI Slicer, so rows are learn / quiz / explore and columns are 3D / MRI. At accessibility sizes the pairs stack. The wordmark and About stop growing at xxxLarge, like a navigation bar (About shows the large content viewer).
- **Glass**: each tile is a `Button` whose style applies `.glassEffect(.clear.tint(…).interactive(), in: .rect(cornerRadius: 26))`, all in one `GlassEffectContainer`. `.regular` glass over the near-black backdrop looked like flat dark cards; `.clear` over the backdrop's rose (lower left) and violet (right) lights picks up their color and bright rims (the lights move to the panel's side in the wide layout). First launch tints the Learn banner with the accent and notes "Start here"; the quiz tiles note "N to review" while Learn has flagged structures (both quizzes ask those first). Accessibility: a tile's label is its title, the subtitle its hint, the note its value.
- **One stack everywhere**: iPad dropped the `NavigationSplitView` sidebar (the most Settings-like part); modes push full screen on iPad too, and `leaveMode` pops the stack.
- **Hero brain** (`HeroBrainView.swift`): the accent glow moved into the view and breathes (`phaseAnimator`) while the meshes load. `HeroSceneView` uses `StageSCNView` so the field of view fits the narrower side, since the stage can now be taller than wide. A sideways drag turns it (a `UIPanGestureRecognizer` that only begins when the movement so far is mostly horizontal, so vertical drags still scroll; deciding from velocity missed synthesized drags whose first velocity reads zero). Letting go coasts: speed decays exponentially to the slow turn's (a quarter left after 0.8 s, capped at 1.5 turns/s) through a custom `SCNAction.timingFunction`, then the slow turn continues in the flick's direction with no seam; letting go after holding still (no movement for 0.1 s) doesn't fling. Mastery changes made while a mode is open aren't applied then (the brain isn't drawn, so the fade would finish unseen); 0.45 s after the menu returns they fade in over 1.4 s.
- **Entrance**: wordmark and About, stats, then the tile rows fade and rise in with a 70 ms stagger (fade only with Reduce Motion).
- **Tests**: UI tests find tiles as buttons (`app.buttons["3D Quiz"]`). `testMainMenuShowsEveryMode` checks every tile is hittable without scrolling at the default text size; `testFirstLaunchInvitesYouToStart` checks the Learn tile's "Start here" value; `testQuizAtAnAccessibilityTextSize` also captures the large-text menu; `testIPadLayouts` checks the tiles sit under the brain in portrait and beside it in landscape.
- **Verified** in the iPhone 17 / iPad Air 11" (M4) iOS 26.5 simulators: screenshots at default, XXXL and AX L text sizes, first launch, iPad portrait and landscape; screen-recording motion profiles of the entrance, tile press, flicks (both directions coast back to the slow turn in ~3 s), a drag that holds still before letting go (no fling), and the post-quiz light-up (logged: applied once, 0.45 s after returning, not during the quiz).


## Academic Restyle + Light Mode (2026-10-15)

- **No gradients, no decorative color**: the menu's mesh/radial backdrop, the hero brain's glow, the score ring's angular gradient and every `.gradient` fill are gone. `Theme.accent` is now ink (near-white on dark, near-black on light; the asset catalog's AccentColor matches), with `Theme.onAccent` for labels on prominent buttons. Gold stars, orange streaks and pink icons became `.primary`/`.secondary`. Color is kept only for the brain (atlas colors, quiz highlights, hero pink/gold and the stat dots that are its legend) and for right/wrong answer feedback (green/red rows, verdict, session bar).
- **Times New Roman everywhere**: `Theme.font(_ style:)` is Times at the text style's size ×1.12 (Times sets small next to SF), `relativeTo:` the style so Dynamic Type still scales; `.headline` is bold. The root view sets `.font(Theme.font(.body))`; `applyUIKitFonts` covers nav titles/subtitles (`UINavigationBarAppearance.subtitleTextAttributes`, iOS 26), bar buttons, the search field and segmented pickers. Menu tiles use `.regular` glass with a hairline border (no colored backdrop to bend); the Learn tile's "Start here" emphasis is a heavier border.
- **Light mode**: `UIUserInterfaceStyle = Dark` was removed from the build settings; About has a System/Light/Dark picker (`Appearance`, `@AppStorage("appearance")` → `preferredColorScheme`). `Theme.stage`/`SceneColors.stage` is black or off-white paper (0.965). The style shader has a `paper` uniform: on paper the x-ray ghost multiplies (`.multiply` blend, `ghostInk`, `ghostInkGain`) instead of adding, so it reads as pencil rather than glow. `SceneKitView` reads `colorScheme` and calls `setStylePaper` on its scene when the scheme or scene changes; `applyStyle(.ghost)` reads the material's current `paper` value, so later restyles keep to it. The hero brain's glow shader likewise draws ink lines on paper (`setGlowPaper`, `heroInk`). MRI slices and the mini brain stay dark in both modes, like a lightbox (the slice ID readback also relies on the near-black background).
